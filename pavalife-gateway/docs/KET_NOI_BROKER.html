03 Chẩn đoán kết nối — broker_check.py

Kiểm 4 bước + tự gửi/nhận lại device.status (round-trip). Chạy TRƯỚC khi gửi dữ liệu thật.

python tools/broker_check.py \
  --broker wss://mqtt-hn-n1.pavalife.com:443/mqtt --mqtt-version 5 \
  --username GW-ROBOT-DEV-001 --password "$PVL_MQTT_PASSWORD" --ca-cert pavalife-ca.pem

[1] TCP reachability            [OK] mở được TCP tới …:443
[2] TLS handshake + chứng chỉ   [OK] TLSv1.3 · CN=… · hết hạn=…
[3] MQTT CONNECT                 [OK] CONNECT thành công (MQTT 5.0)
[4] round-trip device.status     [OK] tự nhận lại bản tin đã gửi
 KẾT QUẢ: TẤT CẢ PASS — broker sẵn sàng dùng.

Mỗi bước FAIL in kèm gợi ý [→]; thoát code 0 nếu PASS (dùng trong CI).

04 Các kịch bản kết nối (copy-paste)

4c · WSS + user/pass — production PavaLife
python pvl_send.py all \
  --broker "wss://mqtt-hn-n1.pavalife.com:443/mqtt" --mqtt-version 5 \
  --username GW-ROBOT-DEV-001 --password "$PVL_MQTT_PASSWORD" \
  --ca-cert pavalife-ca.pem --publish
4b · TLS (TCP) + user/pass
python pvl_send.py all --broker mqtts://broker.lan:8883 --mqtt-version 5 \
  --username gw --password "$PVL_MQTT_PASSWORD" --ca-cert ca.pem --publish
4d · mTLS (chứng chỉ client)
# publisher.py nhánh TLS: thêm certfile/keyfile
self._client.tls_set(ca_certs="pavalife-ca.pem",
                     certfile="gw-client.crt", keyfile="gw-client.key")
4e · Token/JWT (qua trường password)
python pvl_send.py status --broker "wss://…:443/mqtt" --mqtt-version 5 \
  --username GW-ROBOT-DEV-001 --password "$PVL_JWT" --ca-cert ca.pem --publish

--insecure (bỏ xác minh TLS) chỉ để thử tạm — không dùng production.

07 Go-live + bảo mật

Quy trình go-live

  • Điền thông tin §01, đặt CA/secret vào ENV.
  • broker_check.py → TẤT CẢ PASS.
  • pvl_send.py status --publish → bên vận hành xác nhận nhận được …/up/device.status.
  • Gửi thử vitals; bật store-and-forward + LWT; chạy nền (systemd); giám sát device.status (60s).

Checklist bảo mật

  • TLS bật, xác minh CA — không --insecure ở production.
  • Bí mật trong ENV/secret manager, không hardcode/commit.
  • client_id duy nhất; ACL tối thiểu quyền.
  • patient_id chỉ trong payload, không topic/log (rule #10).
  • Rate limit + store-and-forward; LWT device.status=offline.
  • Xoay mật khẩu/cert định kỳ; thu hồi khi lộ.
